質問

同じ形だから8段でも96段でも積める。では素朴に積めば、積んだぶんだけ賢くなる？

  • ならない。深さには税金が2つ：勾配が入口まで届かない／途中のベクトルの大きさが暴れる
  • 今日はこの2つに保険をかけてから、GPT の全身を組む

前回の部品を持ってくる

  • 今日のコードは前回の Head・MultiHead・FeedForward の続き。自分のファイルの続きに書くか、下をコピーして先頭に置く
前回の部品（Head / MultiHead / FeedForward） 
import math
import torch
import torch.nn as nn
import torch.nn.functional as F

class Head(nn.Module):
    def __init__(self, n_embd, head_size, block_size):
        super().__init__()
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.key = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape
        q, k = self.query(x), self.key(x)
        w = q @ k.transpose(-2, -1) / math.sqrt(k.shape[-1])
        w = w.masked_fill(self.tril[:T, :T] == 0, float("-inf"))
        w = F.softmax(w, dim=-1)
        return w @ self.value(x)

class MultiHead(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        head_size = n_embd // n_head
        self.heads = nn.ModuleList(
            Head(n_embd, head_size, block_size) for _ in range(n_head))
        self.proj = nn.Linear(n_embd, n_embd)

    def forward(self, x):
        return self.proj(torch.cat([h(x) for h in self.heads], dim=-1))

class FeedForward(nn.Module):
    def __init__(self, n_embd):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_embd, 4 * n_embd), nn.ReLU(), nn.Linear(4 * n_embd, n_embd))

    def forward(self, x):
        return self.net(x)

バックプロパゲーションを30秒で

  • 学習に必要なのは「各パラメータを動かすと損失がどう動くか」＝勾配。loss.backward() が自動で出してくれるやつ
  • 深いネットは変換の連なり。勾配は、通り道にある傾きの掛け算で入口まで運ばれる（連鎖律 chain rule）

\[ \text{入口に届く勾配} = (\text{部品Cの傾き}) \times (\text{部品Bの傾き}) \times (\text{部品Aの傾き}) \]

  • 例：どの部品も傾きが 0.5 なら、3段で \(0.5^3 = 0.125\)、10段で \(0.5^{10} \approx 0.001\)
  • 1より小さい傾きが続くだけで、入口の勾配は千分の1に痩せる — 勾配消失。深いネットの持病

保険1：迂回路を付ける — 残差接続

  • 対策：部品を迂回路つきにする

\[ x \leftarrow x + f(x) \]

  • 出力＝「元の \(x\)」＋「部品の仕事ぶん」。勾配は足し算の枝を素通りして入口まで届く
  • 残差接続（residual connection）。コードでは x + f(x) と書くだけ

  • 「積む」が「元の情報に修正を足していく」に変わる — 深くしても壊れにくい設計

保険2：入力を揃えてから渡す — LayerNorm

  • 深く積むと、途中のベクトルの大きさがバラバラに育って学習が不安定になる
  • 各位置のベクトルを平均0・ばらつき1に揃える部品を、各部品の直前に置く
import torch
import torch.nn as nn

torch.manual_seed(0)
x = torch.randn(2, 5, 96) * 7 + 3          # 平均3・ばらつき7のベクトルたち
ln = nn.LayerNorm(96)
y = ln(x)
print(f"before: mean {x.mean():.2f} / std {x.std():.2f}")
print(f"after : mean {y.mean():.2f} / std {y.std():.2f}")
before: mean 3.27 / std 7.24
after : mean -0.00 / std 1.00
  • LayerNorm（layer normalization）— 「測る前に平均0・ばらつき1へ揃える」標準化の仲間（テストの素点を偏差値に直すのと同じ発想）
  • 揃えたあとに掛ける・足す用の小さなパラメータ（γ・β）だけ学習される

ブロック — Transformer の1段

  • 4部品を決まった順に組む。この1段をブロック（Transformer block）と呼ぶ
class Block(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        self.sa = MultiHead(n_embd, n_head, block_size)
        self.ff = FeedForward(n_embd)
        self.ln1 = nn.LayerNorm(n_embd)
        self.ln2 = nn.LayerNorm(n_embd)

    def forward(self, x):
        x = x + self.sa(self.ln1(x))   # 揃えて→会議→迂回路で合流
        x = x + self.ff(self.ln2(x))   # 揃えて→考える→合流
        return x

  • ブロックは入口と出口が同じ形（T×n_embd）→ いくらでも積み重ねられる

全身を組む — これが GPT

class GPT(nn.Module):
    def __init__(self, vocab_size, n_embd, n_head, n_layer, block_size):
        super().__init__()
        self.block_size = block_size
        self.tok_emb = nn.Embedding(vocab_size, n_embd)   # 文字の埋め込み
        self.pos_emb = nn.Embedding(block_size, n_embd)   # 位置の埋め込み
        self.blocks = nn.Sequential(
            *[Block(n_embd, n_head, block_size) for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(n_embd)
        self.head = nn.Linear(n_embd, vocab_size)         # 語彙スコアに戻す

    def forward(self, idx):                               # idx: (B, T) 文字番号
        B, T = idx.shape
        x = self.tok_emb(idx) + self.pos_emb(torch.arange(T))
        x = self.blocks(x)
        return self.head(self.ln_f(x))                    # (B, T, vocab) ロジット

model = GPT(vocab_size=3045, n_embd=96, n_head=4, n_layer=2, block_size=64)
logits = model(torch.randint(3045, (2, 10)))              # 2文・各10文字を試しに
print(logits.shape)
print(f"パラメータ数: {sum(p.numel() for p in model.parameters()):,}")
torch.Size([2, 10, 3045])
パラメータ数: 817,125

  • 語彙3,045（『吾輩は猫である』サイズ）で約82万パラメータ

Tweak 設計図の数字で遊ぶ

変えること 何が起きるか
n_layer=2 → 8 パラメータはどこがどれだけ増える？（内訳の勘定で確認）
n_embd=96 → 192 層を増やすのと次元を増やすの、効き方の違いは？
block_size=64 → 128 増えるのは1部品だけ。どれ？（内訳の勘定はヒントにならない — なぜ？）

ここで観察

  • block_size を倍にして増えるのは位置の埋め込み表だけ：64×96 = 6,144 → 128×96 = 12,288。パラメータ的には安い買い物（ただし各ヘッドが作る視線の表は T×T に広がるので、計算の手間は別勘定）
  • 内訳の勘定で pos_emb は「埋め込み」の行に混ざっている — 増分 6,144 はそこに現れる

まとめ

  • 深さの税金は2つ：勾配消失（傾きの掛け算で痩せる）とベクトルの暴れ
  • 残差＝ \(x + f(x)\) の迂回路で勾配を守る。LayerNorm＝部品の前でベクトルを揃える
  • ブロック＝「揃えて会議、揃えて自習、どちらも迂回路つき」。同じ形で積み放題
  • 埋め込み→ブロック×N→語彙スコアで GPT の全身が完成。語彙まわりがパラメータの7割

現在の設計図　文字＋位置 → ［LN→注意→＋］［LN→FFN→＋］×N → 語彙スコア

練習問題

以下の問題をPythonコードで解け。

問題1：迂回路の効果を勾配で確かめる

残差接続の有無で入口に届く勾配がどう変わるか、ミニ実験で確かめよ。

  1. f = nn.Sequential(nn.Linear(16, 16), nn.ReLU()) を10個作り、x = torch.randn(1, 16, requires_grad=True) を用意
  2. 残差なし（x に順に f を適用）と残差あり（x + f(x) を繰り返す）の2通りで出力の合計を backward()
  3. x.grad.abs().mean() を比較（残差ありの方が桁違いに大きいはず）

問題2：語彙のコスト

vocab_size を 3,045（文字レベル日本語）と 65（英語の文字レベル相当）にした GPT のパラメータ数を比べよ。差はどの部品から来るか、内訳の勘定で示せ。

解答例

解答例を見る 
import torch
import torch.nn as nn

# 問題1
torch.manual_seed(0)
layers = [nn.Sequential(nn.Linear(16, 16), nn.ReLU()) for _ in range(10)]

x1 = torch.randn(1, 16, requires_grad=True)
h = x1
for f in layers:
    h = f(h)              # 残差なし
h.sum().backward()

x2 = x1.detach().clone().requires_grad_(True)
h = x2
for f in layers:
    h = h + f(h)          # 残差あり
h.sum().backward()

print(f"残差なしの入口勾配: {x1.grad.abs().mean():.6f}")
print(f"残差ありの入口勾配: {x2.grad.abs().mean():.6f}")

# 問題2
for v in [3045, 65]:
    m = GPT(vocab_size=v, n_embd=96, n_head=4, n_layer=2, block_size=64)
    n_emb = m.tok_emb.weight.numel() + sum(p.numel() for p in m.head.parameters())
    print(f"vocab {v:5d}: 全体 {sum(p.numel() for p in m.parameters()):8,d}"
          f"（うち語彙まわり {n_emb:7,d}）")

残差ありの入口勾配: 6.937421
vocab  3045: 全体  817,125（うち語彙まわり 587,685）
vocab    65: 全体  241,985（うち語彙まわり  12,545）
  • 問題1：ReLU 10段の掛け算で勾配は目に見えて痩せる（30秒リキャップの \(0.5^{10}\) が現物で出る）。迂回路があると入口まで太いまま届く
  • 問題2：ブロック部分は同じなのに全体は3倍近く違う — 大語彙のコストは埋め込みと出口に集中する。実物の LLM が文字でなくサブワード（BPE）を使う理由のひとつ
