訓練データの形 — 1枚で64問

  • 文章を 64文字（block_size）ずつ切り出し、「1文字ずらし」を正解にする
import torch

text = open("data/neko.txt", encoding="utf-8").read()
chars = sorted(set(text))
stoi = {c: i for i, c in enumerate(chars)}

data = torch.tensor([stoi[c] for c in text])
n = int(len(data) * 0.9)
train_data, val_data = data[:n], data[n:]    # 採点用の1割は隠しておく

x = data[:8]                                  # 短い例で仕組みを見る
y = data[1:9]
print("入力:", "".join(chars[i] for i in x))
print("正解:", "".join(chars[i] for i in y))

正解: 

　吾輩は猫で

ミニバッチを切り出す

def get_batch(data, block_size=64, batch_size=32):
    ix = torch.randint(len(data) - block_size - 1, (batch_size,))
    x = torch.stack([data[i:i + block_size] for i in ix])
    y = torch.stack([data[i + 1:i + block_size + 1] for i in ix])
    return x, y

xb, yb = get_batch(train_data)
print(xb.shape, yb.shape)     # (32文, 64文字) が2組
torch.Size([32, 64]) torch.Size([32, 64])
  • ランダムな一部だけで1歩、のミニバッチをここでも使う。1バッチ＝32×64＝2,048問
  • torch.stack は同じ形のテンソル（tensor）を重ねて1段上の次元を作る：64文字の棒32本 → (32, 64) の板

火入れ — 300回だけ回してみる

import torch.nn.functional as F
from gpt import GPT

torch.set_num_threads(1)                     # CPUではこの方が速いことが多い
torch.manual_seed(42)
model = GPT(vocab_size=len(chars), n_embd=96, n_head=4, n_layer=2, block_size=64)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)

for it in range(1, 301):
    xb, yb = get_batch(train_data)
    opt.zero_grad()
    logits = model(xb)                                    # (32, 64, 3045)
    loss = F.cross_entropy(logits.view(-1, len(chars)),   # 2,048問まとめて採点
                           yb.view(-1))
    loss.backward()
    opt.step()
    if it in (1, 100, 200, 300):
        print(f"更新 {it:3d}回 | Loss: {loss.item():.4f}")
更新   1回 | Loss: 8.2259
更新 100回 | Loss: 4.9774
更新 200回 | Loss: 4.2422
更新 300回 | Loss: 4.1335
  • 3拍子の学習ループは一字一句このまま — モデルが GPT になっただけ
  • view(-1, V) は並べ直しだけ：(32, 64, 3045) の答案の束を「2,048行の答案リスト」にして交差エントロピーへ
  • 初期損失は約8.2（\(=\ln 3045\)、何も知らない状態の罰点）。そこから一気に転がり落ちる

生成してみる — 300回時点の実力

@torch.no_grad()
def generate(model, prompt, n):
    idx = torch.tensor([[stoi[c] for c in prompt]])
    for _ in range(n):
        logits = model(idx[:, -64:])[:, -1, :]   # 見えるのは直近64文字まで
        probs = F.softmax(logits, dim=-1)
        idx = torch.cat([idx, torch.multinomial(probs, 1)], dim=1)
    return "".join(chars[i] for i in idx[0].tolist())

torch.manual_seed(0)
print(generate(model, "吾輩は", 80))

クイズ：10,000回回すと何が起きる？

クイズ

損失のグラフはどうなっていると思う？ 訓練データ（見た文章）と、隠しておいた1割（初見の文章）の2本の線を想像してから、めくる。

  • val は2,500回あたりで底（約3.6）を打ち、その後は悪化 — train だけが下がり続ける
  • 32万字を10,000回で約64周も読んだ（\(10000 \times 2048 \div 321139\)）— 同じ本の読みすぎ

過学習、最終決戦

  • 地名MLPの回とまったく同じ形（過学習）が、GPT でも出た — モデルが変わっても病気は同じ
  • 訓練文の細かい癖に最適化が進み、初見の文章への実力はむしろ落ちていく
  • 対策も同じ発想：val が底を打ったところで止めて、その時点の重みを使う — 早期終了（early stopping）と呼ぶ

育った視線を覗く

  • 「束ねて、考える」の回の宿題を回収する — あのときどのヘッドがどんな「係」（視線の分業）になるかは学習まかせと約束した
  • 訓練済みモデルに冒頭の一文を読ませ、層×ヘッドの視線の表（Q・K・V の回で作った「誰が誰を見るか」の表）を取り出して眺める
  • 左（head 1）は副対角線1本：どの文字も直前の1文字だけを重み約99%で見る係 — バイグラムの再発明
  • 右（head 3）は遠くまで広く薄く見る係 — 同じ式・同じデータから、正反対の分業が勝手に育った

「名前はまだ」の視線

  • 「…名前はまだ→（？）」を予測する瞬間（「だ」の行）、この係の視線は「は」に41%、「名」に22%
  • 注目という発想の回の手計算（「まだ」から「名前」へ視線が飛ぶ）が、実物の中で本当に起きている

14文字前のカッコを見る係

  • 「「」と「と」の列に縦の縞 — カッコ・引用の構造を追いかける係
  • 「」」の位置からは、14文字前の「「」に28%の視線。「、」からは12文字前の「と」に85%
  • 窓では届かない距離を、位置ではなく内容で見ている — 固定の窓を捨てて手に入れたものが、ここに写っている

視線と対話する — BertViz

  • 静止画は1枚ずつしか見られない。BertViz というライブラリなら、トークンをなぞって全ヘッドの視線を対話的に眺められる（下の埋め込みで今すぐ試せる）
自分の手元で動かすコード（pip install bertviz が必要） 
import torch
from bertviz import head_view
from gpt import GPT

torch.set_num_threads(1)
blob = torch.load("data/runs/neko/ckpt_best.pt", weights_only=True)
model = GPT(vocab_size=len(blob["vocab"]), **blob["cfg"])
model.load_state_dict(blob["state_dict"])
model.eval()
chars = blob["vocab"]
stoi = {c: i for i, c in enumerate(chars)}

text = "吾輩は猫である。名前はまだ無い。"        # 語彙にある文字なら何でも
idx = torch.tensor([[stoi[c] for c in text]])

maps = []                                        # 各ブロックを歩き直して視線を回収
with torch.no_grad():
    x = model.tok_emb(idx) + model.pos_emb(torch.arange(idx.shape[1]))
    for block in model.blocks:
        h_in = block.ln1(x)
        layer = []
        for head in block.sa.heads:
            q, k = head.query(h_in), head.key(h_in)
            w = q @ k.transpose(-2, -1) / (k.shape[-1] ** 0.5)
            w = w.masked_fill(head.tril[:idx.shape[1], :idx.shape[1]] == 0,
                              float("-inf"))
            layer.append(torch.softmax(w, dim=-1))
        maps.append(torch.stack(layer, dim=1))   # (1, ヘッド数, T, T)
        x = x + block.sa(h_in)
        x = x + block.ff(block.ln2(x))

html = head_view(maps, list(text), html_action="return")
open("attn_view.html", "w", encoding="utf-8").write(
    "<html><head><meta charset='utf-8'></head><body>" + html.data + "</body></html>")
print("attn_view.html をブラウザで開く")
  • 好きな文（語彙にある文字だけ）に差し替えて、お気に入りのヘッドを1つ見つけて「係の名前」を付ける — 隣の人と見つけた係を交換
  • 線の濃さ＝視線の重み。左の列でレイヤを切り替えられる

問題1：何周読んだか

バッチ32本×64文字で10,000回更新したとき、モデルが処理した総文字数を計算し、『吾輩は猫である』（321,139字）の何周ぶんにあたるか求めよ。500回・3,500回ならそれぞれ何周か。

問題2：チェックポイントの中身

ckpt_best.pt を読み込み、以下を表示せよ。

  1. 保存されている語彙のサイズ（len(blob["vocab"])）
  2. モデル設定（blob["cfg"]）
  3. state_dict の中で一番大きいパラメータの名前と形（blob["state_dict"].items() を numel() で比べる）
