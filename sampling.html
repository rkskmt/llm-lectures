実験：毎回1位だけを選んだら

  • 「一番ありそうな文字を選び続ける」のが最強に思える。バイグラムの Tweak で見た argmax 作戦
def gen(prompt, n, temperature=1.0, top_k=None, seed=0):
    torch.manual_seed(seed)
    idx = torch.tensor([[stoi[c] for c in prompt]])
    out = model.generate(idx, n, temperature=temperature, top_k=top_k)
    return "".join(chars[i] for i in out[0].tolist())

print(gen("吾輩は", 60, top_k=1))     # top_k=1 ＝ 常に1位だけ

なぜ堂々巡りになるのか

  • モデルは同じ入力に必ず同じ分布を返す。1位だけ選ぶなら、次の文字も必ず同じ
  • 生成中に「前に見た窓の中身」へ一度でも戻ると、そこから先は永遠に同じ道 — 「ぷんぷん」の正体
  • サイコロ（確率での抽選）は、このループを破る唯一の乱数源。問題は「どれくらい揺らすか」

ツマミ1：temperature

  • softmax の前に、スコアを \(T\) で割る — たったこれだけ

\[ \text{probs} = \mathrm{softmax}\!\left(\frac{\text{logits}}{T}\right) \]

  • \(T < 1\)：スコア差が拡大 → 分布が尖る（1位に集中、無難）
  • \(T > 1\)：スコア差が縮小 → 分布が平らになる（番狂わせが増える、危険）
  • \(T \to 0\)：ほぼ argmax。\(T = 1\)：モデルの分布そのまま
  • 同じモデル・同じ入力でも、\(T\) だけで「こ」の確率が 72% ⇄ 16% ⇄ 2% と変わる

T を手計算サイズで確かめる

  • softmax の回のスコア (2, 1, −1) を、\(T\) で割ってから通すと：
import torch
import torch.nn.functional as F

s = torch.tensor([2.0, 1.0, -1.0])
for T in [0.5, 1.0, 2.0]:
    print(f"T={T}:", F.softmax(s / T, dim=0).round(decimals=3))
T=0.5: tensor([0.8790, 0.1190, 0.0020])
T=1.0: tensor([0.7050, 0.2590, 0.0350])
T=2.0: tensor([0.5470, 0.3310, 0.1220])
  • \(T=0.5\)：スコア差が2倍に開いて1位が独走（0.88）。\(T=2.0\)：差が半分に縮んで接戦（0.55 / 0.33 / 0.12）
  • モデルは1ミリも変わっていない。変わったのは softmax に渡す前の「差の広げ方」だけ
  • \(e^s\) は差の増幅器だった — \(T\) はその増幅率のツマミ

ツマミ2：top-k — 尻尾を切る安全網

  • \(T\) を上げたいが暴走は困る → 上位 \(k\) 文字だけ残して、あとは \(-\infty\) にしてから抽選
  • 票を \(-\infty\) で消す — 因果マスクと同じ手口（softmax の前に消すのが作法）
print(gen("吾輩は", 80, temperature=2.0, top_k=40))
吾輩はあるま品分に、かいるはずよりほといものも近い猫とし得るのを忘れしきりを捉まってあたかなかって見ましまか」
「ハハハハヴ」と念だ、細君もま時はよこはどっち構ってさ
  • 同じ T=2.0 でも、尻尾の3,005文字が消えるだけで「日本語の音」に戻ってくる
  • gpt.py の generate はこの2ツマミ込みで書いてある：
logits = logits / temperature                      # ツマミ1
if top_k is not None:
    v, _ = torch.topk(logits, top_k)
    logits[logits < v[:, [-1]]] = float("-inf")    # ツマミ2（尻尾を消す）
probs = F.softmax(logits, dim=-1)
nxt = torch.multinomial(probs, num_samples=1)      # サイコロ

top-p — 尻尾を「合計」で切る

  • top-k の弱点：常に k 席の固定枠 — 自信満々の場面では広すぎ、大混戦では狭すぎる
  • top-p（nucleus sampling）は席数でなく得票の合計で切る：確率の高い順に足していき、合計が \(p\) に達したら打ち止め
  • 「吾輩は猫であ」の次は1文字（「る」92%）で到達、「吾輩は」の次は299文字 — 枠の広さが分布の形に追随する
  • 自作GPTの generate のツマミは temperature と top-k の2つ。top-p は実物の API を読むための知識として持ち帰る

分布の形を、実物で歩く

  • top-p のカーブが要約していたもの — 位置ごとの分布の形 — をエクスプローラで1つずつ覗ける
  1. いま開いているのは「吾輩は」まで読んだ位置 — 低い棒がずらり（お手上げ型。1位「こ」でも 15.5%）
  2. 「あ」（吾輩は猫であ）の位置をクリック — 「る」が 92% でそびえる（確信型）
  3. プリセットを会話文に替えて、いちばん平らな位置といちばん尖った位置を探す
  4. 見つけた2箇所で「top-p (\(p=0.9\)) の枠に何文字入るか」を目分量で予想 — 尖りは1桁、平らは3桁

ここで観察

  • top_k を小さくしすぎると argmax の「堂々巡り」に近づく — 2つのツマミは同じ「無難⇄暴走」軸を別の方法で動かしている

まとめ

  • 生成のツマミは2つ：temperature（分布を尖らせる/平らにする）と top-k（尻尾を切る）。実物にはもう1つ top-p（合計で切る可変枠）
  • argmax（top_k=1）は堂々巡り、T が高すぎると漢字の豪雨 — 良い文はそのあいだにある
  • 実装は「割る」「-∞で消す」「サイコロ」の3行。ChatGPT の同名パラメータも同じ仕組み
  • 確率的な出力は故障ではなく仕様 — 種（シード）を固定すれば完全再現できる。今日の全セルがそうだった
