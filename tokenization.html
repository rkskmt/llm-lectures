文章を部品に割る — トークン化

  • 文章をモデルに渡す単位に割ることをトークン化（tokenization）、1つ1つの部品をトークン（token）と呼ぶ
  • 割り方は選べる：
割り方 「吾輩は猫である」の例 部品の種類
単語ごと 吾輩 / は / 猫 / で / ある 数十万〜
文字ごと 吾 / 輩 / は / 猫 / で / あ / る 数十〜数千
  • この講義では文字ごとで通す — 部品が少なく、仕組みがぜんぶ見える

番号との対応表を作る

  • 文字→番号の辞書と、番号→文字のリスト。この2つで変換は両方向できる
import pandas as pd

names = pd.read_csv("data/chimei.csv")["yomi"].tolist()
chars = sorted(set("".join(names)))

stoi = {c: i for i, c in enumerate(chars)}   # string to int
itos = chars                                  # int to string（リストのまま使える）
print(stoi["あ"], stoi["ん"])
print(itos[0], itos[73])
0 73
あ ん
  • stoi / itos という変数名はこの先の回でもずっと使う

encode と decode

import pandas as pd

names = pd.read_csv("data/chimei.csv")["yomi"].tolist()
chars = sorted(set("".join(names)))
stoi = {c: i for i, c in enumerate(chars)}
itos = chars

def encode(s):
    return [stoi[c] for c in s]

def decode(ids):
    return "".join(itos[i] for i in ids)

print(encode("しぶや"))
print(decode(encode("しぶや")))
[17, 48, 62]
しぶや
  • 行って戻ってこられる（往復できる）ことが対応表の合格条件

対応表は、機械の入り口と出口

  • 完成形の中で encode / decode がどこに立つか、先に見ておく：

  • モデルの中を流れるのは番号だけ。「し」の字の形も意味も、モデルは一生見ない
  • encode は玄関、decode は出口 — この2つの外側だけが人間の世界
  • ただし番号はまだ「ただの整理番号」— 41番と42番が似ているわけではない。番号に意味を持たせる工夫は「ことばの地図」の回で

演習：往復させる

自作の encode / decode が往復できることを確かめよ。

  1. さっきのスライドのコードを .py ファイルにコピーして実行
  2. 好きな市区町村名（ひらがな）を encode して番号列を表示
  3. その番号列を decode して元に戻ることを確認（== で比較した結果も表示）
  4. 「とうきょう」のようにデータに実在しない並びでも往復できることを確認
解答例を見る 
import pandas as pd

names = pd.read_csv("data/chimei.csv")["yomi"].tolist()
chars = sorted(set("".join(names)))
stoi = {c: i for i, c in enumerate(chars)}
itos = chars

def encode(s):
    return [stoi[c] for c in s]

def decode(ids):
    return "".join(itos[i] for i in ids)

word = "とうきょう"
ids = encode(word)
print(ids)
print(decode(ids))
print(decode(ids) == word)   # True — 実在しない並びでも文字さえ語彙にあれば往復できる

  • 実物の LLM も同じ問題を抱えている：語彙にどんな部品を揃えるかは設計の急所

語彙の外と、どう付き合うか

質問

ChatGPT に絵文字や顔文字を打ち込んでも、KeyError では止まらない。どう解決していると思う？

  • 語彙に無い文字への作戦は、だいたい3択：
作戦 中身 代償
黙って捨てる 知らない文字を無視して続行 入力が化ける（最悪）
「その他」の枠 未知の文字を全部、未知語トークン（unknown token）1つに置き換え 情報が消える
部品を細かくする バイト単位まで割れば何でも表せる 列が長くなる
  • 実物の答えは3つ目：GPT-2 以降の語彙はバイトまで割れる部品を常備 — 地球上のどんな文字列も語彙外にならない
  • 自作の encode が KeyError で止まるのも立派な設計 — 黙って捨てるくらいなら、その場で叫ぶ

『吾輩は猫である』全文（約32万字）に出てくる文字は何種類？ ひらがな＋カタカナで約170、そこに漢字が乗る。1000？ 2000？

  • 3,000超 — 日本語の文字レベル言語モデルは、この大語彙と戦うことになる

出典

青空文庫『吾輩は猫である』（著作権消滅済み）。ルビ・注記を除去したテキスト。

語彙サイズ比較

  • 同じ「日本語」でも、材料しだいで語彙は40倍違う
  • 語彙が大きい＝分類の選択肢が多い＝当てるのが難しい。まずは74択の地名から

第3の割り方 — サブワード

  • 単語ごとは種類が多すぎ、文字ごとは『猫』でも3,045種。実物は中間を取る：
割り方 「吾輩は猫である。」 種類
単語ごと 吾輩 / は / 猫 / で / ある / 。 数十万〜
サブワード 吾輩は / 猫 / である。 数万
文字ごと 吾 / 輩 / は / 猫 / で / あ / る / 。 数十〜数千
  • 作り方は意外なほど素朴：よく隣り合う2文字を数えて、合体を繰り返すだけ（BPE と呼ぶ）
  • 『猫』の前半10万字で実際に回すと、合体20回で「吾輩」「主人」が部品になり、100回で「である。」が丸ごと1部品になる
  • 本編は最後まで文字ごとで通す。合体の職人技は回数外の BPE の付録 で1から自作できる

まとめ

  • ことばを数にする手順：トークン化（文字ごとに割る）→ 語彙（文字一覧）→ 番号の対応表
  • stoi / itos / encode / decode — この4点セットはこの講義の全域で使い回す
  • 語彙に無い文字はエラー — 実物はバイトまで割って逃がす。地名は74種類、『猫』は3,000超、実物のサブワードは数万

現在の設計図　文章 → 文字に分割 → 番号 → モデル → 番号 → 文字

問題1：一番よく使われる文字

地名データ全体（1,747件をつなげた文字列）で、登場回数の多い文字トップ5を回数つきで表示せよ。

  1. chimei.csv を読み込み、"".join(...) で1本の文字列に
  2. 各文字の回数を辞書で数える（collections.Counter を使ってもよい）
  3. 多い順に並べてトップ5を表示

問題2：使われていないひらがな

五十音の基本46文字（"あいうえおかきくけこさしすせそたちつてとなにぬねのはひふへほまみむめもやゆよらりるれろわをん"）のうち、地名のよみに1度も使われていない文字をすべて表示せよ。

問題3：秘密のメッセージ

本編の対応表（stoi / itos）で、次の番号列を decode せよ。

[66, 59, 25, 67, 14, 2, 5, 9, 30, 8, 41, 56, 27, 40, 36, 56, 3, 26]

読めたら、その文はこの講義の次回予告になっている。

from collections import Counter

import pandas as pd

names = pd.read_csv("data/chimei.csv")["yomi"].tolist()
all_text = "".join(names)

# 問題1
counts = Counter(all_text)
for c, n in counts.most_common(5):
    print(c, n)

# 問題2
gojuon = "あいうえおかきくけこさしすせそたちつてとなにぬねのはひふへほまみむめもやゆよらりるれろわをん"
unused = [c for c in gojuon if c not in counts]
print("未使用:", unused)

# 問題3
chars = sorted(set(all_text))
ids = [66, 59, 25, 67, 14, 2, 5, 9, 30, 8, 41, 56, 27, 40, 36, 56, 3, 26]
print("".join(chars[i] for i in ids))
