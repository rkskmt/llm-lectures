# 講義全体のアーク設計 — 続編コース「GPTの中身を開ける」

第1コース（`ai` リポジトリ、全14回・MNIST自作で完結）の続編。対象は IP3200（Python・pandas・matplotlib・API）と AI講義（分類→勾配降下→NN→backprop→NumPy自作→PyTorch→MNIST）を修了した次年次の学生。

設計の根拠は [ai/doc/engaging-lecture-design.md](../../ai/doc/engaging-lecture-design.md)（コールドオープン・クイズ→めくり・1セクション1データ・実データ主義）。執筆規約は `ai/CLAUDE.md` に準拠（スライド区切り・演習レジスタ・EN併記・identity scrub 等）。リポジトリの雛形は `ai` の完全ミラー（cleanslidekit / D2 / peek / badge / 検索 / カード型 index / handouts PDF）。

## コンセプト（1行）

第1コースが「`fit()` という1行を開けて、手書き数字を読む機械を全部品自作した」のに対し、続編は**「次の1文字を当てる」という1つの分類問題を開けて、文章を書く機械（小さなGPT）を全部品自作する**。相似形にする。

初回に置く橋渡しの一言：

> 君たちはMNISTで「画像→10クラスの確率分布」を出す分類器を作った。
> 言語モデルは「文章→語彙全体の確率分布（＝次の1文字）」を出す分類器**でしかない**。
> 損失も同じ交差エントロピーだ。

**この講義で本当に新しい概念は「埋め込み」と「注意」の2つだけ**、と初回に宣言する。これが最大の難易度低減装置。

## 難易度を下げる4つの決定（Karpathy との差別化）

1. **導出しない。** 勾配・初期化・数値安定性の議論は落とす。autograd への信頼は第1コースで獲得済み。「forward は何か・損失は何か」だけ開ける。softmax(QKᵀ/√d)V は「①関連度を測る ②割合にする ③混ぜる」の**3ステップの表計算**として教える。
2. **手計算は1回だけ。** backprop回の「5パラメータ手計算」の再演として、**トークン3個・2次元での attention 手計算**を1回だけ。数値は検算コードで逆算設計（σ(0)=0.5 方式）。
3. **1回1部品＋毎回実験。** 全回に Tweak と演習。どの回も「今日増えた部品は1個」で閉じる。
4. **成果物が「聞こえる」。** 精度の数字ではなく**生成されたことば**で上達がわかる題材（架空地名→文豪文体）。

RNN/LSTM は本編から**完全カット**（MLP言語モデルの「固定窓の限界」が歴史的動機を代替）。BPE は名前だけ紹介して回数外へ。

## 講義全体のコールドオープン：文豪テスト

- 初回に短文を数本見せ、「本物の漱石はどれ？機械が書いたのはどれ？」と投票させる。答えは最終回まで封印。
- 「機械の文」は最終回に組む自作GPTの**実出力**を使う → **参照実装を先に完成させてから初回デッキを書く**（執筆順の制約）。
- 中間回のまとめに番号なしの伏線行（「この部品が文豪テストの種明かしにつながる」）。回数カウントダウンは使わない（`ai` と同じ理由）。

## インタラクティブ可視化の方針（2026-07-10 改訂）

3層で賄う。主役は自作：

1. **自作GPTエクスプローラ（自作ツール、主役）** — `explorer/index.html`。訓練済み ckpt_best の実重み・実活性で、構造図→部品クリック→中身（ヒートマップ／視線の表＋弧／次の1文字分布）。CDN 不要・日本語・講義用語。**段階違いで4箇所に iframe 埋め込み**：qkv回（`#view=attn`、右上が空＝マスクの伏線）／マルチヘッド回（`#view=heads`、係の分業）／深く積む回（`#view=structure`、全身歩き）／訓練回（`#view=predict`、予想の変化）。詳細は §実測ログ
2. **既存の公開デモ** — [LLM Visualization](https://bbycroft.net/llm)（bbycroft）は「実物大」担当として深く積む回に **iframe 埋め込み**（X-Frame-Options なしを実測確認済み）。[Transformer Explainer](https://poloclub.github.io/transformer-explainer/) は ChatGPT までの距離の回に **iframe 埋め込み**（2026-07-10 動作確認済み — Temperature スライダ・Top-k/Top-p 切替・サブワード分割が見える。GPT-2 small）。深く積む回からはリンクアウトのまま。受け身にならないよう「30秒で隣に説明」タスク付き
3. **BertViz** — 視線との対話用に訓練回で採用（§実測ログの BertViz 項）。スライダー系（temperature 等）は plotly 組み込み slider で足りる
4. **plotly iframe（IP3200 方式）** — 埋め込みの d=2 地図は plotly の text scatter で対話化（ズーム・ホバー・凡例切替。初期表示は全域＝「吾」の孤立が最初から見える）。`fig.write_html("iframes/…", include_plotlyjs="directory")` → `::: {.plotly-iframe src=…}`（cleanslidekit の lua）。`iframes/` はレンダー時再生成（gitignore）＋ resources。plotly は environment.yml に追加済み

## 実測ログ（2026-07-08、tools/refimpl/ にて）

観察 callout・スライド本文の数値はここに記録された実測のみ使う。

### 環境・速度

- 実測環境は WSL2 + conda-forge pytorch-cpu（MKL なし）。**スレッドは増やすほど遅い**（1t 289ms/iter、4t 688ms、28t 3.5s — GPT 0.82M・batch32×64）。**講義スクリプトは `torch.set_num_threads(1)` 固定**で、引用する時間はすべて1スレッド実測値。
- 大きい logits（batch×3045）はメモリ帯域で律速。埋め込み可視化の訓練セルは batch 1024 に抑える（4096 だと 330ms/iter）。

### コーパス

- `data/chimei.csv`: **1,747市区町村**、総文字数 9,681、語彙 **75**（境界記号「・」含む）。名前長 min 2 / max 11 / 平均 5.54。**「ー」は地名よみに1度も出ない**。
- `data/neko.txt`: **321,139字、語彙 3,045**。train/val = 前90%/後10%。

### 地名バイグラム（数え上げ、+1平滑化）

- train nll 2.5406 / val nll **2.6246**（一様分布なら ln 75 = **4.3175**）
- 最初の文字トップ: か117, お113, い98, み94, あ88, し88 ／ 最後の文字トップ: **し713**, う416, ち251, ら146
- 「ょ」の次は99%超「う」(454/458)。「っ」の次トップは「ぷ」7（べっぷ等）
- サンプル（seed 1）: 玉石混交 — でたらめ「おおぬびらおめっげぱゃべどてぶぬぎおずくら」〜それっぽい「ひがわむら」「たまち」「ひちたちょう」

### 地名ニューラル・バイグラム（Embedding(V,V)、フルバッチ400step・lr0.5・約7s）

- train nll 2.3379（数え上げ・平滑化なしと同じ最適解に収束）
- **確率表の一致: max |ΔP| = 0.018、平均 0.00025** — 「数えた表と学習した表が一致」の山場は成立
- val nll 2.7834（平滑化なしなので数え上げ+1平滑の2.6246より悪い — 演習ネタ候補）

### 地名MLP（ctx窓、emb8・hidden64、3000step・batch256・lr3e-3、各25s前後）

- ctx1: train 2.398 / val 2.645 ／ ctx2: train 2.023 / val **2.589** ／ ctx3: train 1.860 / val 2.614 ／ ctx5: train 1.817 / val **2.671**
- **val の改善はわずか、ctx を広げると過学習で逆に悪化**（train/val ギャップ拡大 — 第1コースの過学習がそのまま再登場）。ただし**生成名の見た目は明確に良くなる**（つるぎし、おおじたわらまち、みなみちょう…）
- 生成15件中 **13件が実在しない新作**、2件は実在名の再現（みなみちょう、おおのし）
- chimei MLP の埋め込み(d8)の最近傍はノイズ気味（き→ぎ に僅かな信号）— **地名データだけでは埋め込みの構造の主張はしない**

### 『猫』ボトルネック・バイグラム（Embedding(V,2)+Linear(2,V)、1000step・batch1024・lr2e-2、約75s）

- d=2 直接プロット: **ひらがなは右端・カタカナは左下・漢字は中央**に分離傾向（頻出525字に絞ると見やすい）。分離は「傾向」レベル — 断定表現は使わない
- loss はおよそ 8.2 → 4.7-4.9 で頭打ち

### GPT 参照実装（n_embd 96, n_head 4, n_layer 2, block 64 = **817,125 params**、batch32・AdamW lr1e-3）

- 1スレッドで **296 ms/iter**（10,000 iter = 49分）。授業内の体験訓練は 300〜500 iter（2〜4分）
- **本番ラン（`--tag main`、seed42）**：val は **2,500 iter で底 3.6055**、以後過学習で単調悪化（10,000 で train 2.15 / val 4.13）。10,000 iter ＝ コーパス約64周
- **配布チェックポイント `ckpt_best.pt`**：同一スクリプト 3,500 iter（val 3.62、底とほぼ同じ）。`ckpt_main.pt`（過学習版）は author-side（gitignore）
- スナップショット（`snapshots_main.txt`）：iter0 漢字スープ → 50 かな出現 → 500 言葉のかけら → 2000 文の形 → 10000 長い文。**「文字→かな→単語→文」の順に覚える**
- 過学習しても**逐語再現はしない**（greedy でも「吾輩は猫である。名前はまだ無い。」の続きを再現できず）— 0.8M params は 32万字を丸暗記できない。デッキでは「初見への弱体化」として扱う（「丸暗記の吐き出し」とは書かない）

### RNN小史（experiments_rnn.py、2026-07-11）

- 地名 Elman RNN（10,211 params、窓16、batch256、3,000歩）：val の底は **500歩・2.37**。最終は train 1.80 / val 2.82 — MLP窓2（2.59）には底で勝つが、回し続けると過学習で負ける
- 未訓練RNNへ最後の位置だけから勾配を流すと、64文字前の勾配は最後の位置の **10⁻²⁰ 倍**。訓練済みGPTは約 **10⁻³ 倍**
- 幅96・長さ64・batch32のCPU forward：RNN 1層の逐次ループ **1,692.4ms**、GPT 2ブロック全身 **436.7ms**（1スレッド）。RNNは3〜4倍遅い
- 生成15件と曲線・勾配は `data/runs/rnn/` に保存。デッキの断定値はこの成果物から読む

### 幅スケーリング実験（experiments_scaling.py、2026-07-11）

- 『猫』、2ブロック・4ヘッド・block64、batch32、AdamW lr1e-3、seed42、各2,000歩。変えるのは `n_embd = 12, 24, 48, 96, 192` だけ。RTX 4070 Ti SUPER・PyTorch 2.11.0+cu128で5台を同条件測定
- パラメータ数：**80,613 / 165,093 / 354,789 / 817,125 / 2,073,573**（幅16倍で約25.7倍）
- 最良 val loss：**4.3971 / 4.1348 / 3.9086 / 3.6175 / 3.5575** — 5点で単調改善
- 最大モデルは500歩ですでに val **3.7624**。1,500歩で底 **3.5575**、2,000歩では **3.6338** に悪化。一方、最終 train は **2.5287** — 大きいモデルほど速く学び、固定データでは早く過学習する
- 2,000歩の最終 val だけなら幅96（3.6175）が幅192（3.6338）に勝つ。比較には最終値でなく各モデルの best val を使う
- float32重みだけの容量：幅12 **0.32MB** / 幅96 **3.27MB** / 幅192 **8.29MB**。学習時は勾配・optimizer状態・活性が加わる
- 成績・500歩ごとの曲線・同一条件の生成文・実行環境は `data/runs/scaling/` に保存

### 生成のツマミ（sampling.qmd、ckpt_best で実測）

- 「吾輩は」の次の「こ」：T=0.5 で 72.2% ／ T=1.0 で 15.5% ／ T=2.0 で 1.7%
- greedy（top_k=1）は「少々**ぷんぷんぷんぷんぷん**している」の堂々巡り＋シード無関係に同一出力
- T=2.0 は漢字の豪雨、T=2.0+top_k=40 で日本語の音に復帰。T=1.0 の200字：top_k=5 で67種／top_k なしで110種

### 訓練済みモデルの視線（inspect_attention.py、ckpt_best、2026-07-10）

プローブは原文に逐語一致する2文：「吾輩は猫である。名前はまだ無い。」（16字）と「「どっちの方角へ足が向くかね」と主人は真面目な顔をして、」（28字）。

- **L0 H1 は「直前の1文字」係**：直前文字への平均重み **0.993／0.987**（2プローブ）、エントロピーほぼ0。ヒートマップは副対角線1本 — モデルが自力でバイグラムを再発明している。L0 H2 も同系で弱め（0.895／0.830）
- **L0 H0・H3 は遠くを広く均す係**：平均後方距離3〜6文字、エントロピーはほぼ上限
- **L1 H2 は構造（カッコ・引用）係**：会話文プローブで「、」@27 から12文字前の「と」@15 に **0.85**、「」」@14 から14文字前の「「」@0 に **0.28**。ヒートマップでは「「」「と」の列に縦縞 — 窓では届かない距離を内容で見ている
- **「だ」@12（「名前はまだ→無」の直前）**：L1 H3 が「は」@10 に **0.41**、「名」@8 に **0.22** — 視線が「名前は」へ戻る（attention-intuition の作り話がそのまま実物に出る）
- ヘッドごとの分業（1文字係／広域係／構造係）は2プローブで一貫 — 「視線は1系統では足りない」の実証に使える

### 学習された位置埋め込み（ckpt_best、2026-07-10）

- pos_emb 64本の cos 類似度は**対角以外ほぼ0**（隣接位置の平均 0.077、距離2〜16で 0.03〜0.07、距離32で −0.04）。ノルムは 6.9〜10.6
- 「近い位置ほど似る」波模様は**ない** — 64本がほぼ直交の住所札。デッキでは「必要なのは近さではなく**区別**」と書く（サイン波などの期待で書かない）

### BertViz（対話的 attention 可視化 — 採用、2026-07-10）

- `head_view(attn, tokens, html_action="return")` は**自作モデルの生の注意テンソルでそのまま動く**（レイヤごとに (B, n_head, T, T) を渡す）。`from bertviz import head_view` は transformers を import しない — `pip install bertviz --no-deps` で動作確認済み
- ただし `pip install bertviz`（通常）は transformers・boto3・sentencepiece を引き込む（fresh-clone は重くなるが動く）。生成 HTML は **d3/jquery/require.js を cdnjs から読む** — 閲覧時にネット必須
- 生成 HTML はファイル書き出し→ブラウザで開けば VSCode スクリプト運用の学生でも使える

### 自作GPTエクスプローラ（explorer/、export_explorer_data.py、2026-07-10）

- `explorer/index.html` — 自作の対話的モデル可視化（CDN・外部依存なし）。ckpt_best のプリセット2文（冒頭文・会話文）の全部品活性を `data_neko.js`（約690KB）に事前計算。構造図→部品クリックで中身（ヒートマップ／視線の表＋弧／q・k・v／次の1文字分布）

- **実測（explorer データより）**：「吾」の位置の次文字予想1位は「輩」**71.4%**（埋め込み回の「吾→輩90%」の伏線回収に使える）。「だ」（名前はまだ→無）の位置の予想上位は そ4.0%／一3.5%／し2.2% — **「無」は上位に来ない**。視線は戻るが予想は弱い、と書くこと（過大主張禁止）
- 外部デモの iframe 可否を実測：bbycroft.net/llm も poloclub の Transformer Explainer も **X-Frame-Options / CSP なし＝埋め込み可**（2026-07-10 ヘッダ確認）

### 地名らしさ採点（experiments_chimei.py likelihood_ranking、フルデータ・平滑化なし・境界込み平均nll）

- **最も地名らしくない実在名**：**ちよだく 3.780**、ちとせし 3.728、めぐろく 3.566、ねりまく 3.556、ののいちし 3.540（都会の区名が上位を占める）。つくばみらいし 3.476 も10位内

### エッセンススライドの検算数値（verify_claims.py、2026-07-10）

- 内積：(1,1)·(2,2)=4、(1,1)·(1,−1)=0、(1,1)·(−1,−1)=−2
- softmax(2, 1, −1) = (0.705, 0.259, 0.035)、合計1
- −log p：p=0.9 → 0.105、p=0.5 → 0.693、p=0.01 → 4.605、p=1/75 → **4.3175**（学習前の予言と同じ値）
- autograd：x=3、y=x² → `y.backward()` → `x.grad` = **6.0**
- X@X.T（qkv回の動機スライド）：[[1,0,1],[0,1,1],[1,1,2]]（対称）。行softmax(/√2) = (0.401, 0.198, 0.401)／(0.198, 0.401, 0.401)／(0.248, 0.248, **0.503**) — 3文字目は自分を最も見る、1・2文字目も自分が同率1位

### 注意の手計算（attention-intuition / attention-qkv で使用、verify_claims.py で検証済み）

- K=[(1,1),(1,0),(0,1)]、V=[(1,0),(0,1),(1,1)]、q₃=(1,1) → スコア (2,1,1)
- 単純正規化: (0.5, 0.25, 0.25) → 文脈ベクトル **(0.75, 0.5)**（手計算はここまで）
- softmax: (0.5761, 0.2119, 0.2119) → (0.7881, 0.4239)（コードで答え合わせ）
- スケール付き(√2): (0.5035, 0.2483, 0.2483) → (0.7517, 0.4965)

### シャッフル不変性（position-mask）

- pos_emb なしの Head で文脈4トークンを並べ替えても最終トークンの出力差 **1.5e-08**（=完全一致）。pos_emb ありなら logits が変わる（構造的に位置を区別できるようになる）

### 増厚リバイス第2弾の実測（2026-07-10、ckpt_best／neko.txt）

- **質問に答えない実験（to-chatgpt）**：`gen("「君の名前は何かね」", 60, seed=1)` → 改行付きの会話劇の続き（「それでね、どうですかも知れないのは…」）— 質問を登場人物のセリフとして続ける。seed 0・2 も同系。**「：」は語彙 3,045 字に無い**（`stoi["："]` は KeyError）— 「質問：／答え：」形式は入力不能
- **ハルシネーション解剖（to-chatgpt）**：`gen("吾輩の主人は", 60, seed=0)` 中の「**寒月君は猫**としてはならんのだから」— 「寒月君は猫」は本文 **0回**。部品は実在：「寒月君は」**59回**・「猫として」**4回**（「は猫」28回）
- **重さ（to-chatgpt）**：817,125 × 4B = 3.27MB、`ckpt_best.pt` 実測 **3.4MB**（語彙表・cfg 同梱）。`neko.txt` は **0.96MB**（958,243B）— モデルは原作より重い
- **分布の尖り/平ら（lm-introduction）**：「であ」の次＝「る」**962/1,139 = 84.5%**・候補**12種**。「、」の次＝1位「そ」**425/6,773 = 6.3%**・候補**1,044種**。（参考：「吾輩は」の次は こ8.6%／猫5.3%・111種 — 未使用）
- **top-p（sampling、p=0.9 のとき残る文字数）**：「吾輩は猫であ」→ **1文字**（「る」92.2%）／「吾輩は」→ **299文字**／「。」→ 297／「、」→ 342 — 可変枠の実証
- **シード再現（sampling）**：`gen("吾輩は", 40, T=0.8, seed=7)` は2回実行で完全一致、seed=8 は別文。`torch.manual_seed(0)` → `multinomial([0.7,0.2,0.1], 8)` は `[2,1,0,2,0,1,0,0]` が再現
- **盗作チェック（bungo-project の `longest_match`）**：文豪テスト機械文の本文との最長一致は **B=8字**（「るごとく、主人の」）・**D=9字**（「の事じゃありません」）— 既記録の「最長9文字」と整合。本物Aは全文74字一致（検査コードの動作確認）

## 執筆時の申し送り

- **枚数を絞らない（2026-07-10 追記）**：スライド枚数の上限は設けない。1つの概念には「動機（クイズ）→ 実験/図 → 組み立て → 観察」をフルに使ってよい（mlp-lm の多層ネットワーク節＝1枚→5枚が基準密度）。「one slide = one idea」は**枚数を増やす**方向に働かせる — 詰め込み1枚より分割N枚。目安：1回 18〜25枚。
- **図・コード・インタラクティブは説明負荷を下げる投資（2026-07-10 追記）**：入れるか迷ったら入れる。特に（1）**関数は形を必ず描く**（softmax・ReLU・−log・e^s・シグモイド・T のように、式が出たらカーブも出す）、（2）**ネットワークは構造図を必ず添える**（コードだけの部品定義を作らない）、（3）対話できるもの（explorer・plotly・BertViz）は静止画の上位互換として積極採用。
- **前提道具は自己完結で教え直す（2026-07-10 リバイスの中心方針）**：第1コースの道具（softmax・交差エントロピー・3拍子・ミニバッチ・train/val・内積・backprop…）は、**この講義内の初出時に自己完結のエッセンススライド**（`{#peek-◯◯}` アンカー付き）で教え直す。以後の回は `[…](deck.qmd#peek-◯◯){.peek}` で参照。「第1コースの◯◯と同じ」は説明の代役にせず、説明し終えた**後の括弧書き**でのみ使う。
- **torch API は初出時に挙動デモ**：新しい torch の道具（`backward()`・`multinomial`・`topk`・`stack` 等）は、モデルの中で初めて使う前に「これをやるとこう動く」の極小入出力デモを見せる。
- **比喩の再アンカー（2026-07-10 追記）**：擬人化・物のたとえは積極的に使ってよい。ただし**回をまたいで再登場させるときは、初出の回名か一言の言い換えを必ず添える**（例：「窓を広げるの回でやった折れ線細工」「視線の表（誰が誰をどれだけ見るかの T×T）」）。読者の記憶は1回ぶんも飛ばない前提で書く — 前回のたとえでも「前回作った」の一言を挟む。また、たとえの中身と矛盾する呼び方をしない（q・k・v は人が持つ小道具＝名札・探しもの・中身であって「3人」ではない。「係」はヘッドの呼称）。
- **数値の出どころ**：スライドの断定的な数値・観察 callout は §実測ログ にあるものだけ。新しい主張はまず refimpl で測る
- **デッキのコードとシード**：スライドの echo セルは「学生がそのままコピペして同じ出力を得る」ことが正義。乱数はすべて明示シード。数値を引用する場合はデッキの**そのままのコード**を先に単体実行して確認する（モジュール構築順が変わると init が変わり数値がズレる）
- **文豪テストの4文**は bungo_test.txt が正本。ckpt_best を作り直したら4文も作り直し、lm-introduction / bungo-project を同時更新
- 重いセル：embeddings（約1分）・mlp-lm（スイープ約1-2分）・gpt-training（300iter 約2分）。フルレンダーは10分級 — mnist-project と同じ扱い
