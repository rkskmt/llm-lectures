# 講義全体のアーク設計 — 続編コース「GPTの中身を開ける」

第1コース（`ai` リポジトリ、全14回・MNIST自作で完結）の続編。対象は IP3200（Python・pandas・matplotlib・API）と AI講義（分類→勾配降下→NN→backprop→NumPy自作→PyTorch→MNIST）を修了した次年次の学生。

設計の根拠は [ai/doc/engaging-lecture-design.md](../../ai/doc/engaging-lecture-design.md)（コールドオープン・クイズ→めくり・1セクション1データ・実データ主義）。執筆規約は `ai/CLAUDE.md` に準拠（スライド区切り・演習レジスタ・EN併記・identity scrub 等）。リポジトリの雛形は `ai` の完全ミラー（cleanslidekit / D2 / peek / badge / 検索 / カード型 index / handouts PDF）。

## コンセプト（1行）

第1コースが「`fit()` という1行を開けて、手書き数字を読む機械を全部品自作した」のに対し、続編は**「次の1文字を当てる」という1つの分類問題を開けて、文章を書く機械（小さなGPT）を全部品自作する**。相似形にする。

初回に置く橋渡しの一言：

> 君たちはMNISTで「画像→10クラスの確率分布」を出す分類器を作った。
> 言語モデルは「文章→語彙全体の確率分布（＝次の1文字）」を出す分類器**でしかない**。
> 損失も同じ交差エントロピーだ。

**この講義で本当に新しい概念は「埋め込み」と「注意」の2つだけ**、と初回に宣言する。これが最大の難易度低減装置。

## 難易度を下げる4つの決定（Karpathy との差別化）

1. **導出しない。** 勾配・初期化・数値安定性の議論は落とす。autograd への信頼は第1コースで獲得済み。「forward は何か・損失は何か」だけ開ける。softmax(QKᵀ/√d)V は「①関連度を測る ②割合にする ③混ぜる」の**3ステップの表計算**として教える。
2. **手計算は1回だけ。** backprop回の「5パラメータ手計算」の再演として、**トークン3個・2次元での attention 手計算**を1回だけ。数値は検算コードで逆算設計（σ(0)=0.5 方式）。
3. **1回1部品＋毎回実験。** 全回に Tweak と演習。どの回も「今日増えた部品は1個」で閉じる。
4. **成果物が「聞こえる」。** 精度の数字ではなく**生成されたことば**で上達がわかる題材（架空地名→文豪文体）。

RNN/LSTM は本編から**完全カット**（MLP言語モデルの「固定窓の限界」が歴史的動機を代替）。BPE は名前だけ紹介して回数外へ。

## 講義全体のコールドオープン：文豪テスト

- 初回に短文を数本見せ、「本物の漱石はどれ？機械が書いたのはどれ？」と投票させる。答えは最終回まで封印。
- 「機械の文」は最終回に組む自作GPTの**実出力**を使う → **参照実装を先に完成させてから初回デッキを書く**（執筆順の制約）。
- 中間回のまとめに番号なしの伏線行（「この部品が文豪テストの種明かしにつながる」）。回数カウントダウンは使わない（`ai` と同じ理由）。

## 幹は2本

### 第1幹：名前ジェネレーターの物語（1データを貫く）

題材は**日本の地名の「よみがな」**（総務省・全国地方公共団体コード約1,700件。足りなければ日本郵便の郵便番号データの町域名で増量）。ひらがな約70文字なので、バイグラム表が**70×70のヒートマップとして丸ごと目視できる**。数えるだけ→ニューラル→MLP と同じデータでモデルを乗り換え、「架空の市町村名」の質が上がるのを聞き比べる（「1枚のグラフを育てる」の言語版）。

### 第2幹：Attention を開けて GPT を組む

コーパスを**青空文庫**（著作権切れ）に切り替え、注意機構を組み、最終回に**推し文豪ボット**を完成させる。学習中の定点サンプリングで「デタラメ→単語→文」と言葉を覚えていく様子を見せるのが山場。

## インタラクティブ可視化の方針

専用ウィジェットの自作はほぼ不要。3層で賄う：

1. **既存の公開デモをリンクアウト**（見せ場用。受け身にならないよう「30秒で隣に説明」等のタスクを付ける）
   - [Transformer Explainer](https://poloclub.github.io/transformer-explainer/)（poloclub）— GPT-2 をブラウザ内で実行し、全部品をノード図で対話操作できる。attention 回〜block 回の締めに最適
   - [LLM Visualization](https://bbycroft.net/llm)（Brendan Bycroft）— nanoGPT の中身を 3D で歩ける
   - 外部サイトの iframe 埋め込みは X-Frame-Options 次第なので**リンクアウトを基本**とする（要検証）
2. **自作モデルの中身を見せる**：[BertViz](https://github.com/jessevig/bertviz) — attention 行列とトークン列を渡すと対話的 head view の HTML を吐く Python ライブラリ。自作 char-GPT にもそのまま使えるはず（**要検証**）。埋め込みは IP3200 の plotly iframe 資産と同じ方式
3. **スライダー系**（temperature 等）は plotly 組み込み slider で足りる — カスタム JS 不要

## 実測ログ（2026-07-08、tools/refimpl/ にて）

観察 callout・スライド本文の数値はここに記録された実測のみ使う。

### 環境・速度

- 実測環境は WSL2 + conda-forge pytorch-cpu（MKL なし）。**スレッドは増やすほど遅い**（1t 289ms/iter、4t 688ms、28t 3.5s — GPT 0.82M・batch32×64）。**講義スクリプトは `torch.set_num_threads(1)` 固定**で、引用する時間はすべて1スレッド実測値。
- 大きい logits（batch×3045）はメモリ帯域で律速。埋め込み可視化の訓練セルは batch 1024 に抑える（4096 だと 330ms/iter）。

### コーパス

- `data/chimei.csv`: **1,747市区町村**、総文字数 9,681、語彙 **75**（境界記号「・」含む）。名前長 min 2 / max 11 / 平均 5.54。**「ー」は地名よみに1度も出ない**。
- `data/neko.txt`: **321,139字、語彙 3,045**。train/val = 前90%/後10%。

### 地名バイグラム（数え上げ、+1平滑化）

- train nll 2.5406 / val nll **2.6246**（一様分布なら ln 75 = **4.3175**）
- 最初の文字トップ: か117, お113, い98, み94, あ88, し88 ／ 最後の文字トップ: **し713**, う416, ち251, ら146
- 「ょ」の次は99%超「う」(454/458)。「っ」の次トップは「ぷ」7（べっぷ等）
- サンプル（seed 1）: 玉石混交 — でたらめ「おおぬびらおめっげぱゃべどてぶぬぎおずくら」〜それっぽい「ひがわむら」「たまち」「ひちたちょう」

### 地名ニューラル・バイグラム（Embedding(V,V)、フルバッチ400step・lr0.5・約7s）

- train nll 2.3379（数え上げ・平滑化なしと同じ最適解に収束）
- **確率表の一致: max |ΔP| = 0.018、平均 0.00025** — 「数えた表と学習した表が一致」の山場は成立
- val nll 2.7834（平滑化なしなので数え上げ+1平滑の2.6246より悪い — 演習ネタ候補）

### 地名MLP（ctx窓、emb8・hidden64、3000step・batch256・lr3e-3、各25s前後）

- ctx1: train 2.398 / val 2.645 ／ ctx2: train 2.023 / val **2.589** ／ ctx3: train 1.860 / val 2.614 ／ ctx5: train 1.817 / val **2.671**
- **val の改善はわずか、ctx を広げると過学習で逆に悪化**（train/val ギャップ拡大 — 第1コースの過学習がそのまま再登場）。ただし**生成名の見た目は明確に良くなる**（つるぎし、おおじたわらまち、みなみちょう…）
- 生成15件中 **13件が実在しない新作**、2件は実在名の再現（みなみちょう、おおのし）
- chimei MLP の埋め込み(d8)の最近傍はノイズ気味（き→ぎ に僅かな信号）— **地名データだけでは埋め込みの構造の主張はしない**

### 『猫』ボトルネック・バイグラム（Embedding(V,2)+Linear(2,V)、1000step・batch1024・lr2e-2、約75s）

- d=2 直接プロット: **ひらがなは右端・カタカナは左下・漢字は中央**に分離傾向（頻出525字に絞ると見やすい）。分離は「傾向」レベル — 断定表現は使わない
- loss はおよそ 8.2 → 4.7-4.9 で頭打ち

### GPT 参照実装（n_embd 96, n_head 4, n_layer 2, block 64 = **817,125 params**、batch32・AdamW lr1e-3）

- 1スレッドで **296 ms/iter**（10,000 iter = 49分）。授業内の体験訓練は 300〜500 iter（2〜4分）
- **本番ラン（`--tag main`、seed42）**：val は **2,500 iter で底 3.6055**、以後過学習で単調悪化（10,000 で train 2.15 / val 4.13）。10,000 iter ＝ コーパス約64周
- **配布チェックポイント `ckpt_best.pt`**：同一スクリプト 3,500 iter（val 3.62、底とほぼ同じ）。`ckpt_main.pt`（過学習版）は author-side（gitignore）
- スナップショット（`snapshots_main.txt`）：iter0 漢字スープ → 50 かな出現 → 500 言葉のかけら → 2000 文の形 → 10000 長い文。**「文字→かな→単語→文」の順に覚える**
- 過学習しても**逐語再現はしない**（greedy でも「吾輩は猫である。名前はまだ無い。」の続きを再現できず）— 0.8M params は 32万字を丸暗記できない。デッキでは「初見への弱体化」として扱う（「丸暗記の吐き出し」とは書かない）

### 文豪テスト素材（`data/runs/neko/bungo_test.txt`）

- 機械側は `make_bungo_test.py`（ckpt_best、T=0.8、top_k=40、seed 0 と 1）。**コーパスとの最長一致は9文字**（盗作なし）
- A=本物／B=機械(seed0)／C=本物／D=機械(seed1)。lm-introduction と bungo-project の両方がこの表を参照 — 変更は必ず両デッキ同時に

### 生成のツマミ（sampling.qmd、ckpt_best で実測）

- 「吾輩は」の次の「こ」：T=0.5 で 72.2% ／ T=1.0 で 15.5% ／ T=2.0 で 1.7%
- greedy（top_k=1）は「少々**ぷんぷんぷんぷんぷん**している」の堂々巡り＋シード無関係に同一出力
- T=2.0 は漢字の豪雨、T=2.0+top_k=40 で日本語の音に復帰。T=1.0 の200字：top_k=5 で67種／top_k なしで110種

### プロジェクト・パイプライン検証（『銀河鉄道の夜』456_ruby_145.zip）

- 3.9万字・語彙1,050。同一クリーニング正規表現で問題なし。**val は約1,000 iter で底**（2.96）→1,500 で 3.35 に悪化
- 1,500 iter ＝ 128秒（語彙が小さいと『猫』より約3倍速い）。生成は「カムパネルラも不思議そうに…と叫びました」と賢治風
- ガイドライン：**10万字以上推奨、短編は連結**。250 iter ごとに val 表示＋ckpt 保存 →「あとから底を選ぶ」方式

### BPE（bpe-appendix.qmd、『猫』前半10万字）

- 語彙 2,283。20マージ（0.4秒）で「って」「る。」「」と」「**主人**」「**吾輩**」「云う」が出現、トークン数 100,000→91,366
- 100マージ：最長トークン「である。」、トークン数 81,286、「吾輩は」「ところ」「そんな」も1トークン化

### その他デッキ内で使った実測

- 地名フルデータ（1,747件・境界込み11,428組）：argmax 連鎖は「**かわし**」で自然終了。最初の文字トップ か135/お123/い106、最後は し792/う466/ち277。「名前の最後に来られる文字は**6種類だけ**」
- 数え vs 学習（フルデータ、W ゼロ初期化・AdamW lr0.5・100step・17秒）：初期損失 4.3175=ln75 ちょうど、収束 2.346、**max|ΔP|=0.0067**
- 予測しやすさ：最易は「ょ」（0.07）、最難は境界「・」（3.47）
- MLP top3：「かわさ」→ と39%/き34%、「よこは」→ **ま76%**
- 『猫』d=2 埋め込み（batch1024・1000iter・約1分）：フル表バイグラム 4.70 vs d=2 4.79（**609分の1でほぼ互角**）。漢数字（一二三四五六七十）が同域に集合、「吾」は次が90%「輩」ゆえ大外れ位置（シード変更でも孤立は再現）
- 残差の勾配実験（Linear+ReLU 10段）：入口勾配 0.000035（残差なし）vs 6.94（残差あり）
- GPT-2/3 対比表の公表値：GPT-2 = 48層/d1600/25頭/ctx1024/1.5B、GPT-3 = 96層/d12288/96頭/ctx2048/175B（=うちの子の約21万倍）

### 注意の手計算（attention-intuition / attention-qkv で使用、verify_claims.py で検証済み）

- K=[(1,1),(1,0),(0,1)]、V=[(1,0),(0,1),(1,1)]、q₃=(1,1) → スコア (2,1,1)
- 単純正規化: (0.5, 0.25, 0.25) → 文脈ベクトル **(0.75, 0.5)**（手計算はここまで）
- softmax: (0.5761, 0.2119, 0.2119) → (0.7881, 0.4239)（コードで答え合わせ）
- スケール付き(√2): (0.5035, 0.2483, 0.2483) → (0.7517, 0.4965)

### シャッフル不変性（position-mask）

- pos_emb なしの Head で文脈4トークンを並べ替えても最終トークンの出力差 **1.5e-08**（=完全一致）。pos_emb ありなら logits が変わる（構造的に位置を区別できるようになる）
