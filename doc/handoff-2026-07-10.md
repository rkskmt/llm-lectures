## 執筆方針（今セッションで確立 — course-arc に明文化済み）

1. **自己完結**：「第1コースでやった」を説明の代わりにしない。初出エッセンス（`{#peek-◯◯}`）＋以後は peek 参照
2. **枚数を絞らない**：1回 18〜25枚目安。詰め込み1枚より分割N枚（mlp-lm の多層ネットワーク節=5枚が基準密度）
3. **図・コード・インタラクティブは説明負荷を下げる投資**：迷ったら入れる。**関数は形（カーブ）を必ず描く。ネットワークはコードだけにせず構造図（D2）を必ず添える**。torch API は初出時に「これをやるとこう動く」デモ
4. **数値・観察は実測のみ**（course-arc §実測ログが正本。新しい主張はまず refimpl で測ってログに書き、それから本文）
5. **比喩の再アンカー**（第2セッションで追加）：擬人化・たとえは歓迎。ただし回をまたいで再登場させるときは初出の回名か一言の言い換えを必ず添える。たとえの中身と矛盾する呼び方をしない（例：「3人の作り方」→「q・k・v の作り方」に修正済み — q・k・v は人の持ち物であって人ではない）

## 増厚キュー — **完了（2026-07-10 第2弾で全消化）**

全5デッキを増厚し、レンダー＋Playwright 目視検証済み。実測値はすべて course-arc §実測ログ「増厚リバイス第2弾の実測」に記録済み。

1. **to-chatgpt（12→18枚）** — 重さスライド（3.4MB vs 700GB）／BPE プレビュー「語彙は数えて作る」／**Transformer Explainer iframe 埋め込み**（動作確認済み — Temperature・Top-k/Top-p 切替あり）／指示チューニング before 実験（「君の名前は何かね」→ 芝居の続き。「：」は語彙外で質問形式が入力不能、という小ネタ付き）／しつけの台本スライド／**ハルシネーションの解剖**（「寒月君は猫」= 部品実在・組み合わせ架空、でたらめ地名の解剖の再演）
2. **lm-introduction（13→17枚）** — 文豪テスト直後の「何を手がかりに見分けた？」（採点表を最終回まで保管→bungo-project 開封スライドに答え合わせ行を追加済み）／体験ゲームの振り返り分離「当てやすさには濃淡がある」／「吾輩」問いかけ→めくり化／**尖った分布と平らな分布**（「であ」84.5% vs 「、」1,044種の実測対比図）／自己回帰アンロール図（縦積み D2 — 横一列は小さすぎて没）
3. **sampling（13→15枚）** — 聞き比べを問いかけ化（A/B/C 伏せ→めくり）／**top-p スライド**（累積確率カーブ：尖った文脈1文字 vs 平ら299文字）／シードと再現性の1枚（multinomial ミニデモ＋gen 再現）
4. **tokenization（14→17枚）** — encode/decode がモデルの入口・出口に立つ全体 D2／語彙の外との付き合い方（3作戦表、実物はバイトフォールバック）／第3の割り方サブワード（BPE 付録の実測ティーザー）
5. **bungo-project（10→12枚）** — 提出前の盗作チェック（`longest_match`、機械文 B=8字/D=9字で検証済み）／大会の進行（タイムライン＋2部門表彰）
